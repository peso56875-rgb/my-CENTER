# PESO — Premium Reservation Experience

## هدف المشروع
تجربة حجز رقمية سينمائية لعلامة **PESO** التعليمية، مصممة كإطلاق منتج فاخر بدلًا من موقع تعليمي تقليدي. تركز التجربة بالكامل على الانطباع الأول، سهولة الحجز، وبطاقة حجز قابلة للاقتناء والمشاركة.

## المزايا المكتملة
- واجهة عربية كاملة باتجاه RTL وهوية طباعية احترافية تجمع بين `Alexandria` و`IBM Plex Sans Arabic`.
- Hero سينمائي V2 بتكوين غير متماثل، مفاعل برمجي متحرك، terminal حي، CTA واضح، وعنوان المكان.
- نافذة حجز زجاجية فاخرة بثلاثة مدخلات فقط: الاسم، الهاتف، والصف.
- دعم الصفين `First Secondary` و`Second Secondary`.
- تحقق فوري وأنيق من المدخلات، بما يشمل أرقام الموبايل المصرية.
- زر حجز magnetic مع حالة تحميل وحركات micro-interaction.
- حفظ الحجوزات عبر RESTful Table API، وعدم إصدار رقم مؤكد إذا انقطع الاتصال لضمان سلامة التسلسل.
- أرقام حجز متسلسلة `P1`, `P2`, `P3` مع فحص ما بعد الحفظ وحل تعارضات الحجز المتزامن.
- إظهار مكان الحضور «برهمتوش — شارع أبو ليلة» في الـHero ونموذج الحجز والكارت والصورة.
- Success Experience كاملة مع انتقال سينمائي.
- بطاقة PESO فاخرة بتكوين بصري جديد، لوحة QR مستقلة، ختم توثيق، زخارف holographic، وهوية عربية محسّنة.
- QR Code عالي التباين بمستوى تصحيح أخطاء مرتفع، ويحمل معرّف PESO ورقم الحجز الفريد وحالة التوثيق في payload مختصر سريع القراءة.
- انتظار اكتمال الخط العربي والـQR قبل بدء تصدير الصورة لضمان ظهورهما في الملف النهائي.
- مؤثرات انعكاس وإضاءة و3D tilt على بطاقة الحجز.
- إنشاء صورة البطاقة مباشرة عبر Canvas بدقة 4× (3280×2000 بكسل) بدل تصوير DOM، لضمان تحميل ثابت على الموبايل.
- دعم مشاركة ملف الصورة مباشرة على iPhone/iPad، والتنزيل المعتاد على Android والديسكتوب.
- تصميم responsive مخصص للديسكتوب والموبايل مع تخطيط حجز touch-first.
- دعم `prefers-reduced-motion` لتحسين الوصول.
- عناصر HTML دلالية، حالات focus، وإعلانات أخطاء مناسبة لقارئات الشاشة.

## المسارات الوظيفية
- `/` أو `/index.html` — تجربة PESO الرئيسية.
- `/#hero` — الـ Hero.
- `/#reservation` — نموذج الحجز.
- `POST tables/reservations` — إنشاء حجز جديد.
- `GET tables/reservations?page=1&limit=100` — قراءة الحجوزات عند الحاجة إلى لوحة إدارة مستقبلية.
- `GET tables/reservations/{record_id}` — قراءة حجز محدد.

لا توجد query parameters مطلوبة في واجهة المستخدم الحالية.

## نموذج البيانات
الجدول: `reservations`

| الحقل | النوع | الاستخدام |
|---|---|---|
| `id` | text | المعرّف الفريد الذي تديره المنصة |
| `reservation_number` | text | رقم الحجز الحصري |
| `student_name` | text | الاسم الكامل |
| `phone_number` | text | رقم الموبايل المصري |
| `grade` | text | First Secondary / Second Secondary |
| `status` | text | CONFIRMED |
| `reservation_date` | datetime | توقيت إتمام الحجز |

### التخزين
- التخزين الأساسي والوحيد للحجوزات المؤكدة: RESTful Table API في جدول `reservations`.
- يتطلب تخصيص رقم `P` اتصالًا بالجدول المشترك لمنع إصدار نفس الرقم من جهازين غير متصلين.
- لا توجد أسرار أو API keys داخل الواجهة.

## المكتبات والخطوط
- نسخة محلية من `QRCode.js` داخل `js/vendor/` لضمان عمل QR دون الاعتماد على CDN وقت الحجز.
- Canvas API الأصلي في المتصفح لإنشاء وتنزيل صورة البطاقة.
- Google Fonts: Alexandria، IBM Plex Sans Arabic، DM Mono.

## مزايا غير منفذة حاليًا
- لوحة إدارة للحجوزات.
- إرسال WhatsApp/SMS تأكيدي؛ يحتاج خدمة خارجية آمنة أو backend.
- صفحة عامة للتحقق من QR؛ الـQR الحالي يحمل بيانات الحجز نفسها.

3. ربط خدمة رسائل خارجية من خلال backend آمن عند توفره.
4. اختبار بصري نهائي على مجموعة أجهزة فعلية قبل الإطلاق.
